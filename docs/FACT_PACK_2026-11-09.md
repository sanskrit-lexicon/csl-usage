## The verdict

## 1. We do not know (verified negative)

- The only tracker that ever existed — RRZ Piwik, `piwik.rrz.uni-koeln.de/piwik/`, **site id 8**, tracker script dated Jan 2014 (survives at [sanskrit-lexicon.github.io/cologne/highlighter/index_files/piwik_analytics.js](https://sanskrit-lexicon.github.io/cologne/highlighter/index_files/piwik_analytics.js)) — was **deliberately removed in March 2023** by funderburkjim: commits "Remove piwik user tracking" (csl-homepage `1835bf5`, csl-websanlexicon `e07743d`, 2023-03-11; csl-apidev `56f772a`, 2023-03-16; live comment `csl-apidev/listview.php:73-78`).
- The one surviving tracker include (`/js/piwik_analytics.js` on the simple-search page) is `"// 03-11-2023  Empty file."` — a dead stub.
- No analytics, query logging, or access-log processing exists anywhere in the current code (csl-websanlexicon v02 templates, csl-apidev, csl-pywork, csl-orig, csl-homepage, csl-guides, csl-observatory, csl-santam …): NOT FOUND. Only trace of intent: commented-out `//dbg: $fplog = fopen('query_log.txt','w');` at `csl-websanlexicon/v02/makotemplates/web/webtc2/querymodel.php:441`.
- No dataset of real user lookups exists anywhere in the estate (verified across hubs, handoffs, data dirs, filenames). The live GSC/Metrika pullers persist aggregates only, and concern samskrtam.ru, not the dictionaries. GitHub Pages surfaces are tracker-free.

## 2. We can see (three channels)

| Channel | What it holds | Status |
|---|---|---|
| **Apache access logs** | Every lookup, by construction: queries travel as GET URLs (`getword.php?key=…&transLit=…`, `query.php?word=…`, `/entry/<dict>/<key>`) | **Raw logs + limited metrics available now** (MG, 2026-11-09). Retention/extent to be inventoried in the retroactive wave |
| **Historic RRZ Piwik site 8** | Page-view dashboards 2014–2017+ | Existence proven (tracker + 2016 deck); retention at RRZK unknown |
| **Forward capture** | QueryEvent triples + anonymized web statistics | Requires maintainer deployment (ASK_PACKET); see ADR-0002 |

Supporting facts:

- Query flow and normalization (`webtc/parm.php` → transcoder → SLP1 internal key) make the raw→normalized mapping derivable offline; the input scheme is a URL parameter (`transLit=hk|slp1|itrans|roman|deva`).
- Misses are visible in code (`getwordClass.php:61` "not found: …") but return HTTP 200 — so retroactive outcomes are **reconstructed offline** against the dictionary DBs of the time (documented approximation; dictionary versions change slowly).
- Historical actor classes (ADR-0004) are derivable post-hoc: Apache logs carry User-Agent + Referer.
- `csl-santam` queries ride POST bodies — visible only in server logs, not URLs.
- Historical usage figures exist for scale: the 2016 CDSL deck ([PDF](https://dch.phil-fak.uni-koeln.de/sites/dch/Materialien_Aktivitaeten/2016/The_Cologne_Sanskrit_Lexicon_2016-11-11.pdf)) shows AWStats + Piwik dashboards, ≈47,000 visits and ≈440,000 pages/month in 2015–16, 800–1,300 unique visitors/day.

## 3. We can share (aggregates only)

- The university runs an official **anonymized web-statistics regime** (RRZK Matomo): statistics anonymized, no personal data stored, opt-out honored, DNT respected — [ITCC notice](https://itcc.uni-koeln.de/top/datenschutzhinweise-zu-webstatistken). Our aggregates publication aligns with it (ADR-0001).
- Shared shape (settled design): public page = monthly top-100 normalized keys + top misses (k≥5); Zenodo = versioned releases of all keys/counts (k≥5) + methodology README; retroactive wave = dataset v1.
- Honesty caveat for any future "top looked-up words" claim: `getword.php` is a public CORS/JSONP API — third parties deep-link it. Only human-ui actor class counts (ADR-0004).
